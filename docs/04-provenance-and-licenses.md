# 来源、许可证与复用边界

## 参考项目核查

截至 2026-09-29，本地 `ContentPilot` 工作区的跟踪文件为 31 个，当前树和可见 Git 历史没有项目级 `LICENSE`、`NOTICE` 或版权声明文件；Git 未配置远端。其前端锁文件声明的依赖许可证元数据包含 MIT、Apache-2.0、BSD-3-Clause、ISC、MPL-2.0，但这只是依赖元数据，不能推导 ContentPilot 自身源码许可。

因此 CreatorOS 不把 ContentPilot 代码、提示词、示例文章、样式、截图、浏览器接口细节或锁文件复制进新项目，不把参考仓库当作可再许可组件，也不声称参考项目已被授权作为第三方库使用。

当前设计只吸收抽象产品思路：本地保存、编辑室式工作流、适配器隔离、用户明确触发、失败可恢复。这些思路以 CreatorOS 自己的模型和代码实现。

## CreatorOS 后续登记规则

正式开始编码时：

1. 为 CreatorOS 选择并写入项目自己的 LICENSE；若暂不对外分发，在 README 里明确“未授予再分发许可”，不复制第三方声明。
2. Python、npm 和生成工具依赖保留精确版本及许可证清单；新增依赖先检查 SPDX、源码许可证和传递依赖。
3. 任何外部示例代码必须记录来源 URL、版本、许可证、原始文件和是否真的进入仓库；能用抽象接口或自行实现时不复制。
4. 用户上传图片、PDF、文章、视频和平台内容只保存来源/权利状态，不把它们当作 CreatorOS 可再分发素材。
5. 图片、音乐、B-roll、字体与模型输出分别保存授权或未知状态；未知状态禁止自动打包为可发布资产。
6. 生成结果写入 manifest：输入来源、适配器、模型标识（不含密钥）、时间、状态、人工修改和文件摘要。

## 密钥和平台授权

密钥、Cookie、二维码、令牌、登录 profile、账号截图中的敏感内容不进 Git、日志、正文、测试 fixture 或聊天。测试只用假值/脱敏 fixture。平台连接器要区分已配置、已连接、读取成功、草稿提交成功、发布成功；默认只提供用户触发的读取/草稿提交能力，未提供自动发布。

如果将来发现参考项目实际包含缺失的许可证文件或上游声明，先停止复制/分发相关材料，记录新证据并更新本文件；不会通过猜测许可证来扩大权限。
