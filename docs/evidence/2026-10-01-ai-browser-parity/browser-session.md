# AI 浏览器对照验收记录

- 日期：2026-10-01（Asia/Shanghai）
- 工具：真实 ego-browser nodejs / Ego Lite。
- 唯一 TaskSpace：2；页面：p1 ContentPilot、p2 CreatorOS。
- 服务：ContentPilot http://127.0.0.1:18311；CreatorOS http://127.0.0.1:18310。
- 输入：标题“QA 验收：内容保存与追溯”、摘要“仅用于功能验收，不用于发布。”、作者“QA 测试”、正文含编号 QA-1001；另使用有效 PNG 和无效文本封面。
- 隔离边界：使用独立数据目录；不登录、不扫码、不发送、不调用真实平台提交；截图和状态只代表本地运行结果。

## 对照结果

### ContentPilot 原项目

1. 已有草稿编辑后点击“保存这篇草稿”显示保存成功，但刷新页面回到旧标题和旧正文。源码行为是仅对 local-preview 创建新草稿，已有草稿编辑没有更新 API；这构成原项目当前基线缺陷。
2. 新建文章、填入无效封面路径并保存可以完成；提交显示“公众号草稿提交失败：ModuleNotFoundError”。真实微信依赖在本隔离环境不可用，因此未把它记录为提交成功。
3. 页面能明确显示“等待连接”“尚未连接公众号”，但没有真实账号验收结果。

### CreatorOS

1. 公众号草稿已有内容编辑后保存，刷新仍保留修改；显示 ready、本地更新时间和来源追溯。
2. 有效 PNG 封面上传成功；无效文本文件被前端拒绝，提示“封面必须是 PNG、JPEG 或 WebP 图片”，旧封面状态保持。
3. 配置 → 连接 → 读取微信公众号 Mock 连接器后，提交模拟失败、刷新进入 failed，点击重试后变为 submitted。页面同时明确“状态只是本地适配器回执”。
4. 从主题输入 → 本地简报 → 确认简报 → 三平台模板 → 保存为本地公众号草稿完整走通。公众号、小红书、抖音版本独立保存；页面明确“当前使用本地模板”“真实 AI 生成尚未接入”。
5. 热点页面明确“手动入池 · RSS/官方源待接入”；账号分析支持 JSON 数组导入，1 行数据导入成功并显示“这里只做结构性分析”。单对象 JSON 被拒绝为“没有解析到数据行”，说明输入契约需要按页面提示使用数组。
6. 设置页面明确：内容生成“演示模板 · 未连接 LLM”、热点源 RSS/官方源待接入、账号数据官方 API 待接入、发布默认关闭。

## 结论

- 本地内容工作流和草稿交付的核心交互可用，CreatorOS 的已有草稿更新、封面校验、失败后刷新及重试比 ContentPilot 原项目更完整。
- 两者均不能据此宣称真实 LLM 生成、研究采集、图片/视频生成、真实微信草稿提交或“高质量成稿”“越用越强”。
- CreatorOS 当前验收结论：本地流程通过；真实能力不通过/未接入；不能作为原项目真实外部能力的等价替代。
- ContentPilot 原项目的已有草稿编辑不持久化是对照基线缺陷；若要求“效果一致”，应先决定是兼容该行为还是修正为可持久化更新，不能默认为两者已经一致。
